# Migration Guide: 1.14.x → 1.15.0

## Overview

| Category | Details |
|----------|---------|
| **Breaking Changes** | `better-auth` and `@better-auth/passkey` peer ranges narrowed from `>=1.0.0` to `>=1.7.1 <1.8.0`. Projects below 1.7.1 fail to install. |
| **New Features** | Guards for the peer-range and better-auth contract; CI now enforces `format:check`, `version:check`, `check:manifest`. |
| **Bugfixes** | Passkey stub export surface, passkey detection under strict installs, dev-only module banner. |
| **Migration Effort** | ~15 min for the version pins, plus the `@lenne.tech/nest-server` upgrade it depends on. |
| **Cross-repo** | **Yes.** Requires `@lenne.tech/nest-server@11.37.0`. Do not do one without the other. |

---

## Before you start: this is a two-repo change

better-auth is one protocol with two ends. This package is the **client** end;
`@lenne.tech/nest-server` is the **server** end. They must resolve the *same* better-auth minor.

Upgrading only the app produces a workspace where `projects/api` stays on better-auth 1.6.26 and
`projects/app` moves to 1.7.x. In `lt-monorepo` this does **not** error — `pnpm-workspace.yaml` sets
`autoInstallPeers: true` and the two projects are separate workspace packages, so each quietly
resolves its own version. The symptom appears at runtime:

- Every 2FA activation fails with a generic client error.
- The server log shows nothing unusual.
- `pnpm run check` is green in **both** repos, because each is internally consistent.

`@lenne.tech/nest-server@11.37.0` must be published and adopted first, or in the same wave.

## Steps

### 1. Raise the backend

```bash
# in projects/api
pnpm add @lenne.tech/nest-server@11.37.0
```

Then follow that release's migration guide. It carries a **data** migration (`account.issuer`) that
no build step will warn you about: every account row written by better-auth 1.6 has no `issuer`
field, and the 1.7 sign-in route filters on it verbatim. Existing password users cannot sign in
until it is backfilled.

### 2. Pin better-auth on both sides

Pin it workspace-wide so the api and the app cannot drift apart again:

```yaml
# pnpm-workspace.yaml (workspace root)
overrides:
  better-auth: 1.7.1
  '@better-auth/passkey': 1.7.1
```

For a standalone app:

```bash
pnpm add better-auth@1.7.1
pnpm add @better-auth/passkey@1.7.1   # only if you use passkeys
```

> `@lenne.tech/nest-server` additionally peers `@better-auth/core`. This package does **not** import
> it and does not declare it — do not add it to the app on the assumption that "the same range"
> means the same peer set.

### 3. Update this package

```bash
pnpm add @lenne.tech/nuxt-extensions@1.15.0
pnpm install
pnpm run check
```

### 4. Verify the flow that actually breaks

Automated checks cannot see the split — that is the whole point of it. Walk this by hand:

1. Sign in with an existing password user (proves the `account.issuer` backfill worked).
2. Activate 2FA end to end, through to scanning the TOTP URI.
3. Sign out, sign in again, complete the 2FA challenge.
4. If you use passkeys: register one and sign in with it.

## Troubleshooting

**`ERESOLVE` / `ERR_PNPM_PEER_DEP_ISSUES` mentioning better-auth**
Expected, and the change working as intended. Something still resolves better-auth below 1.7.1 —
usually `projects/api` on an older `@lenne.tech/nest-server`. Do step 1, do not widen the range.

**2FA activation fails after upgrading only the app**
The split described above. Check that api and app resolve the same version:

```bash
pnpm why better-auth
```

**Existing users cannot sign in after the backend upgrade**
The `account.issuer` backfill has not run. See the nest-server 11.36.x → 11.37.0 guide, §3.

**Passkeys silently unavailable, with a console warning**
Fixed in 1.15.0 for strict (non-hoisted) installs. If it persists, confirm `@better-auth/passkey` is
installed in the **app** project and not only hoisted at the workspace root.

**An advisory lands on 1.7.x with the fix only in 1.8.0**
Do not widen the peer range locally as a habit. Override it temporarily and open an issue so both
framework repos move together:

```jsonc
// consumer package.json — temporary
"pnpm": { "peerDependencyRules": { "allowedVersions": { "better-auth": "1.8.x" } } }
```

## Rollback

The change is a manifest narrowing; nothing in the app's own code has to change.

```bash
pnpm add @lenne.tech/nuxt-extensions@1.14.0
```

Roll back the backend and the `overrides` block in the same step, and keep both ends on the same
better-auth version — a rollback that splits them reproduces the failure this release closes.
Note that the `account.issuer` backfill from nest-server 11.37.0 is additive and does **not** need
to be reverted; better-auth 1.6 ignores the field.
