# Migration Guide: 1.25.x → 1.26.0

**Security fix (DEV-4082). The bump alone closes the leak in a copied `2fa.vue`**: a 2FA page that
stored the session token as the JWT signs in on the cookie session after the update, and nothing
readable holds the token any more.

## Overview

| Category | Details |
|----------|---------|
| **Breaking Changes** | `LtPasskeyAuthResult` has no `session` any more. `useLtAuth().twoFactor` is typed and always present. A value that is not a JWT is refused by `jwtToken`, `setLtJwtToken()` and the sign-in methods, including placeholders like `'a.b.c'` in tests. |
| **New** | `useLtAuth().twoFactor.verifyTotp()` / `verifyBackupCode()` finish a 2FA sign-in. `isLtJwtShaped()` in `/lib`. |
| **Bugfixes** | Better-Auth's session token no longer ends up in the readable `lt-jwt-token` cookie (see below). The README sign-in example reads `requiresTwoFactor` from `result.data`. |
| **Migration Effort** | Usually none. Only code that reads `authenticateWithPasskey().session` or writes non-JWT test tokens has to change. Moving a hand-written 2FA page to the new helpers is recommended. |
| **Cross-repo** | Works with nest-server 12.6.0. nest-server 12.6.1 additionally keeps the session token out of these response bodies on the server side. |

The major digit tracks Nuxt (1.x is Nuxt 4), so a breaking change ships as a minor.

---

## What was wrong

Better-Auth answers `POST /iam/two-factor/verify-totp` and `verify-backup-code` with
`{ token, user }`, and `POST /iam/passkey/verify-authentication` with `{ session, user }`. The
token is its **session token**, the value the API keeps in the httpOnly `iam.session_token` cookie,
and nest-server forwards these routes unchanged.

A 2FA page that took this `token` for a JWT wrote it into `lt-jwt-token`:

```ts
jwtToken.value = token;   // the session token
setUser(user, 'jwt');
```

Unlike the session cookie, `lt-jwt-token` is readable by every script on the page. One XSS was
enough to take the session, for its whole lifetime (7 days by default). The nuxt-base-starter
`2fa.vue` did exactly this, and every project created from it has a copy.

## What 1.26.0 does

- **`lt-jwt-token` holds a JWT or nothing.** `jwtToken`, `setLtJwtToken()`, `switchToJwtMode()`,
  `attemptLtJwtSwitch()` and `signIn` / `signUp` refuse any value that `isLtJwtShaped()` rejects.
  That is the same test as nest-server's `isJwtShaped`: three segments, header `eyJ`.
- **Leaked values are deleted.** A value in `lt-jwt-token` that is not a JWT is removed on start and
  on read, together with the JWT mode it came with. The httpOnly session cookie keeps the user
  signed in.
- **`useLtAuthClient().twoFactor.verifyTotp()` / `verifyBackupCode()`** return the answer without
  the session token. A copied `2fa.vue` therefore takes its cookie branch: `setUser(user, 'cookie')`,
  then `switchToJwtMode()`.
- **`setUser(user, 'jwt')` without a stored JWT** signs in on the cookie session and fetches the JWT
  from `/iam/token`.
- **`authenticateWithPasskey()`** never stores the session token and returns `{ success, user }`
  only.

## Steps

### 1. Update

```bash
pnpm add @lenne.tech/nuxt-extensions@1.26.0
```

Vendored projects: update the core (`/lt-dev:frontend:update-nuxt-extensions-core`).

### 2. Only if your code reads `authenticateWithPasskey().session`

Remove it. The result is `{ success, error?, user? }`. If you need the session, read it through the
cookie session (`useLtAuth().validateSession()`); never store its token.

### 3. Only if your tests write placeholder tokens

`jwtToken.value = 'a.b.c'` or `setLtJwtToken('abc')` is now refused. Use a JWT-shaped value:

```ts
const JWT = 'eyJhbGciOiJFZERTQSJ9.eyJzdWIiOiJ1c2VyLTEifQ.c2lnbmF0dXJl';
```

### 4. Recommended: move the 2FA page to the helpers

```ts
const { twoFactor } = useLtAuth();

const { error } = (await twoFactor.verifyTotp({ code })) as { error?: { message?: string } | null };
// or: twoFactor.verifyBackupCode({ code })
if (!error) {
  await navigateTo(redirectTarget);
}
```

They set the user on the cookie session and fetch the JWT from `/iam/token`. Remove any
`jwtToken.value = …` and `setUser(…, 'jwt')` the page did itself. Starter-based projects take over
the starter's updated `app/pages/auth/2fa.vue` once it is released.

### 5. Type change you may notice

`useLtAuth().twoFactor` was `unknown`. It is now always present and typed (`verifyTotp`,
`verifyBackupCode`, plus the client's other two-factor methods). Casts like `as any` still compile.
